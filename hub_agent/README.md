# Haitoo HubStudio 连接器

本机连接器连接当前桌面用户的 HubStudio，获取环境、上传目录并执行 ERP 下发的矩阵任务。设备、环境、方案、运行、日志及人工处理统一在 ERP 的“TK 矩阵”页面管理。本机不提供工作页、账号密码登录页或业务接口。

连接器必须以员工当前桌面用户运行，不能部署在 ERP 服务器，也不能作为 Windows Service 运行。关闭 ERP 网页不影响已创建的服务器任务；退出连接器会使该电脑离线。

## 首次连接

1. 请公司管理员先在「企业管理 → 矩阵管理 → 成员授权」开放矩阵使用权限；再启动并登录 HubStudio，确认当前团队及 Local API 可用。
2. 在 ERP 下载匹配系统和架构的包。正式版：Windows 运行 EXE 安装向导；macOS 从 DMG 将应用拖入“应用程序”后启动。内部版：完整解压 ZIP 到固定目录，保留图形程序、控制台程序与启动脚本的相对位置；Mac 应用先移入固定目录再运行。正式版与内部版按渠道分发，首次安装后继续沿用对应渠道。
3. 首次启动自动打开 ERP 的“TK 矩阵”页面。使用 ERP 账号登录，确认是自己启动的连接器后，点击“授权此电脑连接器”。账号密码只在 ERP 登录，电脑令牌仅保存到系统凭据库。
4. 在 ERP 的“设备管理”中配置当前 HubStudio 团队的稳定 ID。同一团队的多台电脑填写相同 ID；不能用电脑名或邮箱代替。当前已验证的 Local API 列表契约未提供可信的团队身份查询，因此这一项由 ERP 保存，下发给连接器。
5. 平台管理员在 admin「公司与账号」的公司配置中开启「启用 TK 矩阵」。连接器自动获取完整环境并上传服务器，环境出现在 ERP 列表中；也可在 ERP 点击“同步环境”。

已有有效电脑授权直接重连；授权失效后重新打开 ERP 配对页面。配对链接十分钟有效，不把电脑令牌放进 URL，也不把 ERP 登录令牌发给回环服务。更新时保留安装身份和配置，不覆盖原有日志或系统凭据。

本机 `127.0.0.1:45679` 只保留 `/health`，供 ERP 检测连接器是否运行，不提供 HTML、业务数据或任务控制。浏览器提示本地网络访问权限时，允许后可正常检测。托盘菜单提供连接状态、版本与更新进度、检查更新、打开 ERP、打开日志、登录自启开关和退出。默认在当前用户登录桌面后启动，可在托盘关闭。

## 环境与任务

- 连接器每 60 秒从 HubStudio 当前用户及团队获取完整目录。所有分页成功后，按白名单分片上传，服务器原子提交。失败保留上次完整目录，不用部分结果覆盖。
- 环境名称、编号、分组及绑定账号名称可进入目录；密码、2FA 密钥、代理凭据和 IP 不上传。ERP 按公司及设备访问关系展示环境。
- Hub 团队身份在 ERP 保存。修改身份会清除该设备的旧目录访问关系，等待重新同步；设备有排队、运行中或待人工处理的运行时，禁止修改身份。
- 方案、定时、站点覆盖、任务预览、执行、停止及人工处理都在 ERP 操作。公司开关与成员的采集、上品授权均由服务端校验；收回权限后不接新任务，已有任务收到停止请求并保留结果记录。新版连接器只领取 ERP 矩阵任务，不再使用旧本机策略领取协议4任务。历史上品记录和锁保留，旧任务需先核对平台结果再处理。
- 超过五分钟未成功上传的目录不用于领取新的浏览器任务；固定采集包重传不重新打开浏览器。同环境任务继续使用服务器串行锁和 fencing。
- 当前仅启用马来西亚（MY）跨境店，商品入口为 `https://seller.tiktokshopglobalselling.com/product/manage?shop_region=MY`，内置自动上品入口为 `https://seller.tiktokshopglobalselling.com/product/batch/publish?step=2&shop_region=MY`。按站点与店铺类型维护入口配置；采集固定使用内置跨境适配，自动上品可使用内置上传流程或签名插件。内置流程复用任务页面，校验固定文件及页面解析商品数，导入前记录提交意图，并按明确的成功导入数量核对回执。结果不明时进入人工处理。公司开关和成员「使用矩阵」授权仍由 ERP 控制；能力声明不代表真实页面验收。
- 连接器使用当前 HubStudio 登录态，不切换团队；按选中的环境编号启动浏览器；上品直接进入批量上传页，采集进入商品管理页，组合任务先上品后采集，不再请求或等待平台店铺身份接口；结果按环境归档。页面登录失效或采集失败时保留本次页面供人工核查，不关闭用户已有页面。

## 本机开发

后端使用项目的本机 Docker 环境，前端优先使用 Vite 热更新。连接器直接运行源码，修改后重启即可，不需要重新打包。先退出已有连接器以释放 45679 端口。

在项目根目录运行：

```bash
export HAITOO_LOCAL_DEBUG=1
export HAITOO_API_URL=http://127.0.0.1:8001
export HAITOO_PORTAL_URL=http://localhost:5173
.venv/bin/python hub_agent/haitoo_hub_agent.py console
```

显式启用本机调试后，仅允许回环 HTTP；其他地址仍要求 HTTPS。调试按 API 地址隔离系统凭据和默认配置、日志目录，不影响正式环境授权。`HAITOO_AGENT_DATA_DIR` 可指定开发配置与日志目录。连接器仍连接真实 HubStudio，请使用专用测试环境。

当前只读采集在浏览器登录会话中按商品列表接口读取 MY 跨境商品管理页“在售”的全部分页、商品ID、近28天浏览次数和完整SKU（平台SKU ID、规格、商家SKU、库存、MYR价格）。通过列表参数批量返回SKU，必要时读取SKU明细接口，无需逐个展开商品。商品管理页完成后，继续读取“数据分析－商品数据分析”的“按商品－全部”列表，使用最近30天（含今天）的日期窗口，并核对页面起止日期。所需指标列未展示时，在自定义指标中补选GMV、商品曝光次数、商品点击量和商品成交件数，保留已有其他列。分析数据使用页面正常请求的商品分析接口按每页500条批量读取，按商品ID合并到在售商品；平台排序导致跨页重复时，使用商品ID搜索接口精确补查遗漏商品。GMV读取接口本期MYR原始金额，以十进制金额汇总完整去重分析列表的全部商品，保存为店铺GMV；在售商品单独保留明细金额。分析列表跨页去重后不完整时，店铺展示在售商品已知金额小计及覆盖数；接口本期流量及成交件数用于计算CTR和动销率，页面占比、环比及表格渲染不参与数值解析。按商品ID精确查询且接口明确返回零条的商品保留未知指标及无记录原因，并展示分析数据覆盖数和已知指标小计；其他缺失值、缩写值或不完整分页会阻止发布新快照。浏览次数取接口 `last_28days_pv` 原值，`--`保持未知，不推断精确日期窗口。商品数据读取完成后，进入“管理订单－全部”标签页，读取当前页面明确显示的订单总数，核对重复显示的数量一致后保存为独立的全部订单指标，与商品分析时间窗口分开。订单页读取失败或数量不明确时停止发布本次快照。遇到安全验证时在本次页面提示人工处理，最多等待10分钟；不修改库存或价格。

只读采集由 ERP 后台授权后执行，无需本机配置。旧配置中的 `matrix_collection_validation_sites` 不再控制能力声明；Hub 团队身份始终在 ERP 配置。

回到正式环境前退出调试连接器，执行 `unset HAITOO_LOCAL_DEBUG HAITOO_API_URL HAITOO_PORTAL_URL` 后重启。默认正式 API 为 `https://api.haitorok.com`，ERP 为 `https://erp.haitorok.com`。

## 构建与分发

正式支持 Windows x64、macOS Apple 芯片和 Intel；各目标须在对应系统与架构构建、签名并真机验收。Windows ARM64 暂不提供正式下载。

### 内部调试构建

macOS 在 `hub_agent` 目录运行 `./build_macos.sh`；Windows 运行 `.\build_windows.ps1 -RunTests`。默认生成内部测试 ZIP；若内置公钥为空则无法在线更新。要在平台发布内部 ZIP，使用下述内部发布模式，额外生成更新 ZIP 和公司的签名清单。

### 内部 ZIP 发布（无商业代码签名证书）

两种系统都必须配置公司的 Ed25519 发布私钥、公钥和密钥 ID，配置方式与正式构建共用。无需 Windows PFX、Apple Developer ID 或公证凭据：

```bash
cd hub_agent
./build_macos.sh --internal-release
```

```powershell
cd hub_agent
.\build_windows.ps1 -RunTests -InternalRelease
```

Windows GitHub Actions 勾选 `internal_release`，不勾选 `release`，只需配置 `HAITOO_RELEASE_PRIVATE_KEY_BASE64` Secret 和 `HAITOO_RELEASE_KEY_ID` Variable，并将对应公钥写入仓库。两个发布选项不能同时勾选。

内部发布生成首次安装 ZIP、`-update.zip` 与 `-manifest.json`。安装程序与更新包共享公司签名清单，仍检查 Ed25519、包和文件摘要、协议、系统与架构。渠道写入构建元数据及签名清单，不能用服务器参数或环境开关让正式安装跳过系统签名检查。内部模式仅不强制商业代码签名与 Apple 公证；系统仍可拒绝运行，不能承诺静默更新。

内部与正式渠道各自选择最高已开放版本。相同系统、架构和版本仍保持内容不可变，不能把已发布正式版改成内部版，或反向替换；切换分发形式须增加版本号。旧安装入口不能识别内部更新清单时，需要先手动安装支持内部更新的入口一次。

### 正式构建

两种系统都需要：

- 在 `trusted_keys.json` 内置 Ed25519 发布公钥，格式 `{key_id: base64原始公钥}`。服务端 `MATRIX_RELEASE_PUBLIC_KEYS` 配置同一公钥库；空公钥库拒绝更新。
- `HAITOO_RELEASE_PRIVATE_KEY` 指向构建环境中的离线 PEM 私钥，`HAITOO_RELEASE_KEY_ID` 为对应公钥 ID。私钥、代码签名证书及公证凭据不得进入仓库或上传 ERP。
- 固定安装入口也内置公钥。更换发布信任根时，须先重新安装同时信任新旧公钥的正式安装程序，不能只替换服务器公钥；常规版本沿用同一发布密钥即可自动更新。保留回滚版本需要的旧公钥。

macOS 另配置 `HAITOO_MAC_SIGN_IDENTITY`（Developer ID Application）及 `HAITOO_MAC_NOTARY_PROFILE`（已保存的 notarytool 钥匙串凭据），运行：

```bash
cd hub_agent
./build_macos.sh --release
```

流程依次签名嵌套程序和应用、公证并装订应用、生成 DMG、签名并公证装订 DMG、生成保留应用内链接的更新 ZIP，最后签署同时包含安装包和更新包摘要的清单。应用使用固定 bundle ID。macOS 在用户数据目录创建版本槽，无需覆盖 `/Applications` 中的固定入口。

Windows 另安装 Windows SDK 的 SignTool 和 Inno Setup，配置 `HAITOO_WINDOWS_CERT_SHA1`（当前证书库中可用于签名的证书指纹）；工具不在 PATH 时设置 `SIGNTOOL_EXE`、`ISCC_EXE`，运行：

```powershell
cd hub_agent
.\build_windows.ps1 -RunTests -Release
```

流程签署并验证程序、生成用户级 EXE 安装程序、签署并验证安装程序，生成完整更新 ZIP 和签名清单。安装到 `%LOCALAPPDATA%\Programs\HaitooHubAgent`，不创建 Windows Service，日常更新无需管理员权限。旧版本正在运行时先退出，安装与卸载均不删除用户数据或系统凭据。

每个目标产生 `HaitooHubAgent-<系统>-<架构>-<版本>.exe` 或 `.dmg`、`-update.zip` 和 `-manifest.json`。正式签名工具缺失、内置公钥为空或与签名私钥不匹配时构建失败，不生成可正式发布的清单。`min_launcher_version` 为最低固定入口版本；默认与首个支持正式更新的入口一致，变更启动协议时须在签署清单时提高该值。

### 平台发布和私有存储

平台 admin 的“连接器版本”统一上传、测试、开放稳定版与撤回；公司矩阵管理仅保留总览统计与设备管理。安装包和更新包存入 `R2_HUB_EXPORT_BUCKET` 对应的私有桶，复用既有 R2 凭据，禁止开放该桶公共读取。正式文件按版本、系统、架构和 SHA-256 寻址，不覆盖同版本内容。数据库只保存签名清单、发布状态、测试设备 ID 和操作记录，不保存程序二进制。

管理端先提交签名清单，再使用有效期 15 分钟的临时上传链接直传两个文件，绕过代理请求体上限。后端分块读回校验后，使用 ETag 条件复制到正式目录，最后将记录变为草稿；未完成的上传不会进入下载或设备更新列表。同清单重新上传可重试，已归档文件不会被临时链接覆盖。

私有桶配置 CORS：只允许实际管理端域名和本机测试的 `http://127.0.0.1:5174`（需要时）作为 Origin，允许 `PUT` 方法和 `Content-Type` 请求头。为 `connector-staging/` 配置一天后删除的生命周期；不得对正式 `connector/` 前缀应用该清理规则。上传失败检查网络、CORS 和存储权限，私有桶仍保持不公开。

发布顺序为草稿 → 指定测试设备 → 稳定版；管理员也可在外部完成验收后直接开放稳定版。系统、架构与发布渠道分别开放，首次下载与自动更新选择同一最高适用版本。测试设备使用 ERP 设备详情中的 ID，测试版本不会进入通用首次安装列表；测试设备的更新处理区可以按已有访问权限下载向该设备开放的测试安装包。手动下载先校验登录、公司及设备权限，再签发有效期 5 分钟的私有存储链接，由浏览器直接下载安装包并显示进度；网页不缓存整个安装包。链接过期或下载失败时重新点击下载。撤回立即停止签发新链接并阻止暂存包激活；已签发的链接在剩余有效期内仍可使用，已开始的下载可能继续，不强行中断已安装设备。问题版本修复须提高版本号。较老稳定版仍保留，撤回最新版本后可供首次安装使用，已升级设备不会自动降级。

### 自动更新与恢复

首次配对后、每次启动立即检查；运行中每 15 分钟加少量随机延迟检查。后台下载与心跳、当前任务并行，验证发布签名、包和逐文件摘要、系统、架构及协议；正式渠道还验证系统代码签名。下载进度在托盘和 ERP 设备详情展示。新版本暂存完成后暂停领取，等待当前任务收尾，并再次确认平台尚未撤回该包，再由独立辅助进程切换。

固定安装入口内置一个完整可用版本，启动时跳转到当前已验证版本槽。升级保留设备身份、配置、系统凭据和任务记录。新版本确认本机配置、凭据库、核心模块和回环服务可用后才提交指针，远程 ERP 或 HubStudio 临时离线不触发回滚。失败自动恢复旧版本，更新事务支持中断恢复。无法恢复时明确提示手动安装，不误报已恢复。保留当前与上一版本，其余无引用版本在升级成功后清理。

网络故障按退避策略重试，不永久隔离发布包；签名、内容校验和启动失败才隔离对应摘要。磁盘空间不足保留旧版本。入口版本不满足时在 ERP 重新下载安装程序。退出连接器后，可运行 `rollback --kind agent` 或 `rollback --kind plugin` 恢复上一已验证版本，存在未完成更新事务时先等待恢复。

## 验证与日志

在项目根目录运行：

```bash
PYTHONPATH=hub_agent .venv/bin/python -m unittest discover -s hub_agent/tests
PYTHONPATH=backend:backend/tests .venv/bin/python -m unittest discover -s backend/tests -p 'test_tk_matrix.py'
npm test --prefix frontend
npm run build --prefix frontend
```

健康探测测试只使用临时回环端口。浏览器专项通过显式 `HAITOO_BROWSER_TESTS=1` 启用，不使用用户店铺会话。

日志统一使用 UTF-8：macOS 默认 `~/Library/Logs/HaitooHubAgent/agent.log`，Windows 默认 `%LOCALAPPDATA%\HaitooHubAgent\agent.log`；本机调试使用对应 API 的隔离子目录。日志可能包含平台页面信息，排错时不要公开原文中的敏感数据。

具体平台验收状态见 [验证记录](../docs/tk-matrix-validation.md)，签名与快照契约见 [TK 矩阵设计](../docs/tk-matrix-upgrade-design.md)。

## 更新失败后的人工处理

流程为自动下载 → 验证并尝试更新 → 失败恢复旧版 → 在托盘和 ERP 设备区显示指导与手动安装入口。指导入口即使本机回环探测失败仍可在 ERP 使用，不通过本机网页执行系统授权。

- `PermissionError` 或明确的执行权限拒绝显示“系统或文件权限拒绝启动”；新进程退出、超时等不明失败显示“新版启动检查失败”，不武断归因为 SmartScreen 或 Gatekeeper。
- 恢复提示持久保存，普通版本检查和重启不会覆盖；成功升级后清除。手动安装相同或更高版本、通过本机启动健康检查后，也会清除旧失败提示。设备令牌、安装身份、任务记录和配置保留。
- 托盘“更新处理步骤与手动安装”打开 ERP 指导；“处理后重试更新”只重试经过公司签名验证的失败版本。ERP 中设备所有者或公司管理员也可对在线设备请求重试，命令绑定失败摘要且去重，最长保留一天，等待当前任务结束后处理。
- 包签名、摘要、正式代码签名校验失败，以及入口／渠道不兼容，不提供绕过校验的重试；应下载可用安装包或由管理员发布修复版。已撤回、未向设备开放或无权访问的包不提供下载。
- Windows 仅在系统实际提供时选择“更多信息 → 仍要运行”；macOS 仅在“系统设置 → 隐私与安全性”实际提供时选择“仍要打开”。没有例外选项、提示恶意软件或被企业策略禁止时联系管理员，不关闭系统防护。启动脚本不再自动清除 macOS quarantine 属性。
- 手动安装先等待任务结束并退出连接器。内部 ZIP 完整解压到固定目录，正式包按安装向导或 DMG 流程安装；重新启动后核对 ERP 在线状态和版本。下载区显示当前可用版本，可能高于之前失败版本。


### 秒杀续期源码调试

源码连接器设置 `HAITOO_LOCAL_DEBUG=1` 且实际连接本机回环 ERP 地址时，会向 ERP 上报 MY 商家秒杀续期能力并使用内置适配器。重启连接器后等待心跳更新，再重新创建执行预览；旧预览不会自动刷新。调试会使用所选 Hub 环境的真实店铺会话，点击执行会按任务配置处理活动，页面结构不匹配时明确失败。此入口不代表平台验收通过。

打包连接器或连接远程 ERP 时不使用此调试入口，秒杀能力仍需安装声明该能力的已验收签名插件。`HAITOO_LOCAL_DEBUG` 不绕过 ERP 公司、成员、环境权限及活动级租约和回执校验。


“同步秒杀活动”使用独立只读能力 `promotion.flash_sale.collect`，从店铺活动抽屉发起，不会终止、复制或发布活动。同步能力与续期能力分别声明；源码本机调试同时开放两者，正式插件需要实现 `collect_flash_sales` 并明确声明对应能力。仅声明续期能力的旧插件不会自动获得只读同步能力。
