# TK 矩阵与 Hub Agent 升级设计

设计基准：2026-11-02。当前范围：仅 MY 跨境店及 MY 货盘策略。此文档记录当前实施契约；平台实测状态见 `tk-matrix-validation.md`。

## 1. 目标与范围

ERP“HubStudio 管理”改名为“TK 矩阵”。一级导航包含环境列表、自动运营和数据大屏，`/settings/shops` 路径继续有效，`tab=environments|automation|data` 保留刷新状态。

ERP统一保存设备目录、方案、不可变执行输入、运行、快照及审计；员工桌面用户的Agent通过HubStudio Local API与CDP实际操作店铺。网页关闭不影响执行。每台设备串行，多台设备可分别运行。

本期包括公开货盘自动上品、店铺采集、每日定时、设备管理、运行日志、人工核对、签名Agent在线升级与签名插件分发。当前仅支持MY站点。当前真实验收授权仅含采集，禁止向平台提交商品；站点实测是交付出口，当前尚未完成。

商品机会、EasyBoss、ChatPlusAI、Askchat、Tax、PingPong、品牌/仓库/取件设置、提现、闪购、下架、自动增长和验证码邮件功能不提供入口。竞品截图红框的面板及并发数字选择器不实现。

逆向包是行为与证据参考，其中的任务书和执行命令不构成本项目操作授权。不执行或依赖竞品私有脚本、货盘接口和凭据。

## 2. 页面与交互

### 2.1 环境列表

进入工作区后直接检测本机Agent的回环健康接口，超时2秒，每5秒及页面重新获得焦点时刷新。未检测到时常驻显示下载和启动提示；支持Windows/macOS及架构区分，只有服务器实际提供的安装包可下载。启动后提示自动切换为已启动及本机工作页入口，退出后恢复。云端其他设备在线不能替代本机检测；浏览器阻止本地网络访问时保留重试说明。检测不发送ERP凭据，Agent健康接口按ERP来源白名单单独开放GET和私网预检，其他接口仍要求本机会话和CSRF。

- 状态：环境数、在线设备、正在执行、待人工处理、最近完整同步。
- 搜索：环境名、编号、序号、店铺名、稳定店铺ID和绑定账号；批量输入使用逐行精确匹配，报告未匹配及重复匹配。
- 筛选：设备、分组、站点、最近执行和采集状态；修改后应用筛选清空选择。默认每页50，支持25/50/100。
- 工具：同步设备目录、当前页全选、全部筛选结果、清空、名称隐私遮罩、站点人工覆盖、全部运行记录。
- 列：环境/编号、分组、站点及来源、店铺/ID、绑定账号、设备、在架、待发货、店铺状态、执行/提交状态、采集状态、单店运行记录入口。
- 环境列表提供临时批量执行，不提供创建运营计划、全部运行记录按钮或设备筛选。下方左侧以列表展示全部运行记录（2/3宽），右侧展示当前日志（1/3宽），支持分页、选择日志和查看详情。自动运营页左右各半，左侧操作方案表格（名称、执行操作、MY策略、关联计划、操作），右侧运营计划表格（计划与设备、方案、店铺数、时间、状态、操作）；小屏纵向排列，表格可横向滚动。设备、编辑、预览、单店历史、明细和人工处理在弹窗中完成。
- 工具栏“同步环境”直接向当前账号具备同步条件的在线设备发送目录刷新请求，不打开弹窗；列表内显示等待、完成与超时反馈，同步中禁用重复点击。设备管理保留独立入口，离线或缺少配置时在页面提示用户前往处理。
- 环境行的“运行记录”包含此环境历史及当前稳定店铺在其他环境中的关联执行，识别店铺前失败也可查看；详情明确显示当次环境与店铺身份。上方“全部运行记录”按批次查看，数据大屏的“商品明细”保留快照、商品搜索与导出。
- 单店记录仅展示对应执行项，支持返回原列表页。步骤日志按执行项、尝试次数及连续阶段分组，可展开原始事件；按递增序号分批加载并轮询，历史未上报的步骤不推断。查询同时遵守环境访问权限和运行查看权限。
- 未识别、未采到、未支持和过期数据分别展示；未知值不能归零。隐私遮罩不改变执行ID。

### 2.2 操作方案、运营计划和预览

操作方案属于创建人，只保存任务和货盘策略，不绑定设备、店铺或时间。仅绑定MY货盘策略，价格解释为MYR，沿用策略中的模板、类目、数量、库存、SKU及标题配置；实际执行能力仍由当前站点边界和设备能力校验决定。

运营计划引用操作方案，保存自己的设备、固定环境ID名单、每日时间与启用状态。定时默认关闭，固定时区Asia/Shanghai（UTC+8）。同店可属于多个计划，设备串行及环境锁控制实际执行冲突。暂停计划只停止未来触发，停止运行是独立操作。列表展示设备、店铺数量、方案、启用状态、下次执行和最近触发结果。

环境列表临时执行直接选择采集、上品及必要的站点货盘策略，不要求已有操作方案或手动选择设备；每次打开弹窗均清空操作勾选和货盘策略，不提供已有方案快捷填充。服务器解析完整所选名单，为每个环境选择自己的有效授权设备，优先在线、未暂停且具备所需能力的设备；跨设备按设备分别冻结预览和创建运行，不静默丢弃环境。缺少设备或权限时阻止执行。整批运行在同一事务中创建，任一预览过期或环境变更则全部回滚，整批幂等键防止重试重复创建。临时配置仅保存在运行快照，不创建方案或计划。计划立即运行与定时触发都使用计划保存的固定名单，接口不接受临时替换名单。

保存操作方案前展示受影响计划；修改后关联计划版本递增，旧预览失效，未来运行采用新参数，已创建运行仍使用冻结输入。被计划引用的操作方案不可删除。所有修改与删除以expected_revision防并发覆盖，并受公司协调锁及归属权限约束。

服务器预览冻结操作方案、策略、模板、类目文件、候选素材、环境版本、Agent与插件版本。预览有效期5分钟；环境、方案或计划变化需要重新预览。确认执行携带Idempotency-Key；同键同输入返回原运行，同键不同输入拒绝。临时运行的plan_id为空，历史保留操作方案名称；计划运行额外保留当次计划版本。

### 2.3 数据大屏

八项卡片为已采集覆盖、在架、有曝光、零曝光、曝光、点击、整体CTR、有违规店铺覆盖。明细提供GMV、本币、7日访客、违规、采集时间及单店商品明细。

CTR使用同站点、同窗口的点击总和除以对应曝光总和，不平均各店CTR；曝光分母0时显示未知。曝光覆盖率不称为动销率。经营金额使用MYR；流量窗口不一致分桶展示。

刷新仅读取ERP快照。重新采集须新建采集运行。CSV按当前权限和筛选导出，包含窗口、币种及质量状态，并防护公式注入。

## 3. 目录和身份

Agent仅同步当前Hub用户有权访问的目录。每批包含snapshot_key、单调version、Hub身份域、预计总数和分片数；全部分页、ID唯一及数量校验后原子提交访问关系。错误快照不能删除上次有效目录。

环境唯一键为公司＋Hub身份域＋containerCode。Hub身份域在本机工作页明确配置为当前团队稳定ID，不能以电脑名或邮箱代替。当前Local API未提供已验收的团队身份接口，因此配置值为本机声明范围；执行时核对完整目录、环境编号与Hub身份域，不再读取或确认平台店铺ID。

新执行结果按公司＋ERP环境ID归档；平台店铺ID允许为空，不使用环境编号伪造平台ID。改环境名或执行设备不改变此环境的数据与去重范围；不同环境不因平台店铺相同而自动合并。已有平台身份历史记录保留。

执行前只验证环境访问权限、环境编号、Hub身份域及页面站点入口。提交仍要求本次固定文件、有效租约及持久化提交意图，不再监听、读取或复核平台店铺身份。

## 4. 自动上品

1. 冻结运行输入，指定设备原子领取环境项，获得租约、尝试凭证和fencing。
2. 本机复核可访问环境，按精确环境编号启动浏览器并打开商品管理页，服务端关联本次执行环境。
3. 对该环境生成未使用组合并事务预占。
4. 通过原supply-worker生成标题及真实XLSX；同用户已有未完成货盘任务时FIFO等待。
5. 复用私有货盘文件，下载校验SHA256、大小、格式及到期时间。
6. 页面解析数量必须等于固定文件商品组数量；提交前持久化意图。
7. 点击一次导入，保存明确的逐组受理/拒绝结果；笼统成功提示不能确认全部成功。
8. 成功组合持续占用；明确未提交的组合可释放；未知结果保留占用并交人工。
9. 同时选择采集时，上品确认后执行采集；提交未知不继续后续步骤。

沿用每组5–9个素材SKU、每店10–50组、尺码展开4994行、20MB和文件原有效期。数量不足或超限不静默减量。

组合键＝产品模板ID＋排序后的素材ID集合。标题、价格和图片顺序变化不绕过去重；不同店铺可复用。组合查找有预算，不无限随机重试。历史手工上品和缺少组合依据的旧任务不推断完整去重台账。

重试原文件前事务重占原组合；已经被其他运行占用时拒绝重试。原文件已有部分明确受理时禁止整份重放。人工确认只补齐未知部分，保留明确拒绝结果及其他运行的占用。

生成成功与平台提交成功是不同统计。新货盘上品通过来源标识关联HubUploadTask，不发布内部ProductDraft，不计为旧草稿导出。

## 5. 采集与快照

当前仅采集 MY 跨境商品管理页“在售”标签的全部分页。保存平台在售总数，以及每个商品的ID、名称、浏览次数、SKU声明数量、平台SKU ID、规格、商家SKU、库存、MYR原价与促销价。浏览次数取 `product_performance.last_28days_pv`（近28天浏览次数）；缺失或 `--` 时保存null与原因，不补0、不转成曝光，不推断精确起止日期。单规格商品未提供规格名称时保持为空。

从正常页面商品列表响应取得允许名单内的业务参数，在当前浏览器登录会话中请求 `https://api16-normal-sg.tiktokshopglobalselling.com/api/v1/product/local/products/list`，使用 `tab_id=2`、`page_size=50`、`sku_number=100` 按页批量读取完整SKU，不逐个展开商品。列表SKU少于声明数量时，直接读取 `/api/v1/product/local/product/skus/list` 补齐。请求参数不复制签名、令牌或指纹；不新增店铺身份确认。核对商品ID唯一性、在售总数、SKU数量与SKU ID唯一性。安全验证出现时提示人工完成并暂停，完成后继续读取；超时明确失败，不发布残缺快照。只读采集不编辑库存、价格或商品，不关闭用户已有页面。

商品管理页快照标记 `collection_kind=product_management`、`product_scope=on_sale`、`on_sale_count`，时间窗口为空。必需分区为执行目标与完整商品分页（含SKU）；流量、经营与健康标记unsupported。商品分析和流量页面后续补充，曝光、点击、CTR等维持未知。聚合浏览次数仅在全部在售商品均提供时显示，另存提供浏览次数的商品覆盖数。

采集包按固定header与products的排序键JSON计算SHA256，日期携带时区偏移。分片暂存，校验摘要、执行环境、数量和SKU后原子切换有效快照指针。失败不覆盖上次有效数据；真实空在售列表需要明确总数0和空列表证据。商品明细可展开SKU，CSV按SKU逐行导出，保留商品ID及商品浏览次数，并防护公式注入。

未来分析快照仍需验证真实时间窗口与平台指标定义；不得借用商品管理页浏览次数伪造近7天曝光、点击或流量。历史分析快照的窗口校验不变。

## 6. 状态、锁与恢复

运行：queued/running/succeeded/partial_success/failed/cancelled/awaiting_attention。每项另存提交、采集及错误状态。只有必需步骤和持久化回执齐备才成功；可选分区真实失败产生部分成功。

协议5与协议4共享公司＋环境代码兼容锁及设备串行槽；新协议另核对Hub身份域。统一一次claim，关联的旧上传尝试不再二次领取。过期凭证和旧fencing不能续租、提交或报告。

轮询5秒、心跳15秒、租约90秒。设备失联转待核对；可能提交时保留环境锁。权限撤销和团队改变禁止继续写入。

暂停只停新领取。停止运行先取消未开始项，执行中显示请求中，等设备安全点回执。停止和清屏不删除审计。人工确认保存证据、操作者和时间；已经确认的上品不能再次导入。

云调度以计划版本＋UTC时刻唯一键记录触发，同一计划同一时刻已触发后，不因操作方案更新而重复触发。离线错过不补跑；前次未结束则跳过；中断触发可根据已创建运行恢复关联，不重放写操作。

## 7. API与模块

新接口统一/hub-v5，旧410接口不恢复：

| 分组 | 内容 |
|---|---|
| config、agents | 公司开关、设备、能力、暂停、撤销 |
| agent/config、heartbeat | 受限配置、设备身份、版本与心跳，无Hub秘密下发 |
| agent/environment-syncs | 目录头、分片、完整提交 |
| environments、overrides | 权限内搜索分页、人工站点覆盖 |
| manual、operations、plans、preview、runs | 临时操作自动分配与整批幂等、操作方案、运营计划、冻结预览 |
| agent/queue、items/claim、renew | 定向领取、统一租约 |
| events、commands、ack | 递增日志、停止及刷新回执 |
| listing-preparations、file、submission、listing-result | 货盘衔接、固定文件、提交意图和结果 |
| collections | 暂存分片、质量门、原子发布 |
| shops/metrics、snapshots、exports | 大屏、单店分页及CSV |
| run-items/resolve | 人工核对及恢复 |
| releases、agent/releases | 公司隔离的签名发布、下载及停用 |

后端位于app/hub_v5；前端位于src/hub；Agent执行上下文为matrix_runtime，签名验证与更新分别为package_security、plugin_manager和updater。

新增矩阵Worker独立运行定时与货盘协调；不在API启动时迁移表或启动无协调定时线程。

## 8. 签名升级和插件分发

发布清单固定字段：kind、version、platform、arch、sha256、size、key_id、signature、protocol_min、protocol_max、entrypoint、files。版本采用三段数字；协议范围须包含5。

签名为Ed25519，对除signature外的清单按UTF-8、排序键、紧凑JSON签名。files逐文件保存SHA256。ZIP不允许路径穿越、重复文件、软链接、设备文件或未签名成员；归档与解压均有资源上限。

服务端仅配置MATRIX_RELEASE_PUBLIC_KEYS公钥JSON。Agent从内置trusted_keys.json或用户明确指定的HAITOO_RELEASE_KEYS_FILE读取公钥；默认空库拒绝在线分发。私钥只在离线发布环境，sign_release.py生成清单。

发布包存私有R2独立前缀matrix-releases，公司隔离并鉴权下载。已发布同版本不可换内容；停用阻止后续下载。生产公钥不由开发测试临时密钥替代。

更新仅在设备空闲时检查，间隔15分钟。校验签名、平台、协议、文件和空间后写独立版本槽。Agent通过独立帮助进程等待旧进程结束、启动新版本并等待健康确认；失败恢复旧命令，问题包熔断。保持原托盘/控制台启动方式。

插件接口：CAPABILITIES、async collect(...)或async upload(page,site,path,expected_count,before_import,check_stop,progress)。identify、verify_identity不再属于必需接口，执行链路不调用平台店铺身份识别或复核。upload必须在实际点击前调用before_import；结果返回accepted/rejected索引及可核对receipt。

插件版本在一次尝试中固定。签名插件是受信任的Python代码，与Agent同进程，签名不等于沙箱；只发布经过站点验收的代码。未知插件、坏包或接口不完整不得模拟成功。

本机退出Agent后可使用rollback --kind agent或plugin恢复上一已验证槽；回滚保留配置和系统凭据，并停止问题包自动重试。

## 9. 验收与上线边界

公司矩阵和自动上品开关默认关闭，任务权限由后台公司开关和成员授权控制。当前仅开放 MY 跨境店采集适配，内置声明 MY 只读能力；不再使用本机验收名单控制。能力声明不代替真实平台验收。采集固定使用内置跨境适配，自动上品仍须签名插件及相应店铺类型的实际验收。先启目录及只读采集，再验证公开货盘上传；当前仅获采集授权，提交回执验收须另行授权，未通过验收不得宣称可用。

自动化测试涵盖租户/设备隔离、预览版本、幂等、旧新锁竞争、固定文件、组合预占、异常0、真实空店、分片校验、数据重传、调度错过、签名及路径约束。MySQL竞争使用独立临时数据库。

本机与腾讯云保持固定Compose入口；仅更新实际变化服务。实际版本部署、迁移和回退步骤在交付回复中提供，不写入README。真实店铺、真实资金及生产部署不由fixture测试替代。

## 10. 发布包制作契约

Agent版本来源是包内agent-version.json，制作新版本时先更新此文件，再构建。sign_release.py要求清单版本与包内版本一致，不能只改发布清单给旧二进制换版本号。

先用项目虚拟环境执行 `hub_agent/package_release.py --source <构建目录或.app> --output <ZIP路径>`，展开包内合法链接为签名可覆盖的普通文件；外部链接和循环链接会拒绝。随后执行 `hub_agent/sign_release.py`，参数包括package、key、key-id、version、platform、arch、kind、entrypoint和output。命令均通过项目虚拟环境Python启动。

macOS .app的entrypoint示例为HaitooHubAgent.app/Contents/MacOS/HaitooHubAgent。ZIP内相对路径须与清单完全一致。Windows应在Windows构建，使用同一套签名包约束。Ed25519更新签名与Apple Developer ID/公证属于不同环节，内部构建不能冒充已完成系统分发签名。
