# 公司公开货盘实施方案

日期：2026-10-14。本文是待实施设计方案。

## 1. 已确认范围与推荐结论

用户已确认：

- **公司独立货盘**：通过某公司的邀请注册，只能使用该公司的公开模板和已上架素材。
- **允许跨链接复用素材**：同一商品链接内不能出现重复素材或重复基础 SKU，不同商品链接可以复用。

推荐将功能拆成“公司货盘发布”“外部用户与邀请”“策略与异步生成”“使用追溯”四部分。首期完成邀请注册、模板公开、素材上架、策略生成、后台处理、R2 下载和使用审计的完整闭环。

这里的“公开”指对该公司获邀请并登录的货盘用户开放，不表示任何人可以匿名访问公司素材。一个任务只使用一家公司的一个产品模板、一份 TikTok 导入类目库和一个商品类目。

“生成链接”表示生成 TikTok 批量上传 Excel 中的商品条目；实际商品 URL 由用户向 TikTok 导入并发布成功后产生。首期任务完成只表示 Excel 已生成，不表示 TikTok 商品已上架。

## 2. 现有项目可以复用的能力

| 能力 | 当前实现 | 方案中的使用方式 |
| --- | --- | --- |
| 登录和公司隔离 | `backend/app/security.py`、`User.company_id` | 复用登录；增加货盘用户身份及明确的 API 权限边界 |
| 素材与永久 SKU | `MaterialAsset` | 作为货盘素材来源；保留来源 ID、SKU 和图片 |

| 类目管理 | `TiktokCategoryCatalog` | 公开指定的公司 TikTok 类目库，复用类目、必填属性和输入选项 |
| 草稿构建 | `build_product_library_draft` | 提取图片、基础 SKU 和尺码映射的公共逻辑 |
| TikTok Excel | `backend/app/tiktok_export.py` | 复用本土、跨境适配器和原始模板保真处理 |
| DeepSeek 标题 | `generate_draft_title` | 复用接口封装，增加公司凭据、结构化错误和后台重试 |
| 数据库队列 | `task_worker.py`、统计 Worker | 新增货盘专用 Worker，继续使用 MySQL 持久队列 |
| 私有 R2 Excel | `storage.py` 的 Hub 导出能力 | 提取通用私有文件接口，增加货盘目录及授权下载 |

三个需要明确处理的兼容点：

1. 现有素材查询和删除对员工使用 `is_operator()` 限制本人数据。新增身份不能依赖“不是员工”的默认分支，否则可能得到整家公司素材权限。旧业务 API 必须明确允许哪些内部角色。
2. 当前前端登录刷新会同时请求模板、素材、草稿、店铺等数据。货盘用户应使用独立的初始化流程和页面入口。
3. 当前 `/drafts/export-tiktok` 会增加导出计数，并将草稿标记为已发布。货盘只复用表格构建和校验逻辑，自己的任务状态使用“Excel 已生成”。

## 3. 页面与操作流程

运营端在左侧“产品库”下方增加“公开货盘”，按权限展示以下子页：

| 子页 | 主要内容 | 可用身份 |
| --- | --- | --- |
| 货盘浏览 | 模板、SKU 图片、筛选、详情、可用素材数量 | 公司内部用户、货盘用户 |
| 上下架管理 | 本公司素材、状态、批量上架/下架、失败原因、使用统计 | 公司管理员、货盘管理员 |
| 我的策略 | 新建、编辑、复制、停用策略及生成前检查 | 可使用货盘的登录用户 |
| 生成记录 | 自己的任务、进度、链接明细、兜底标题数量、下载 | 可使用货盘的登录用户 |
| 货盘用户与邀请 | 创建邀请、注册用户、邀请归属、停用账号 | 公司管理员、货盘管理员 |
| 使用记录 | 按用户、邀请人、模板、SKU、任务、日期查询 | 公司管理员、货盘管理员 |

公司管理员可在成员管理分配“货盘管理员”；产品模板编辑页增加“公开到货盘”开关及发布校验。

素材库增加货盘状态和批量操作。普通员工可以看自己素材的货盘状态；首期上下架由公司管理员或货盘管理员统一执行。货盘管理员即使没有原素材库的员工访问范围，也能通过专用货盘管理接口管理本公司全部符合条件的候选素材，接口不返回创作提示词或其他内部数据。

外部货盘用户登录后进入货盘浏览，导航仅显示货盘浏览、公开模板、我的策略、生成记录和个人账户。公开模板展示名称、封面、产品说明、尺码、尺码图、包装参数及可用素材数量，不展示 AI 提示词、公司内部人员数据和服务密钥。

## 4. 身份、权限与邀请归属

当前 `User.role` 是单角色字段。推荐保留内部成员的原角色，为“货盘管理员”增加附加授权记录，避免把员工改成管理员后丢失原来的工作权限。

- 外部用户：新增 `SUPPLY_USER` 身份，`company_id` 固定为邀请所属公司，不参与员工代码、运营小组、店铺分配和内部成员选择。
- 货盘管理员：作为可叠加的业务角色，由公司管理员授予内部成员或组长。不得自己授予权限，不得跨公司管理。
- 公司管理员：默认拥有本公司的全部货盘管理权限，可分配和撤销货盘管理员。
- 超级管理员：继续使用平台管理入口进行必要的平台管理，管理操作留痕。

| 操作 | 公司管理员 | 货盘管理员 | 普通内部成员 | 外部货盘用户 |
| --- | --- | --- | --- | --- |
| 浏览本公司已上架货盘 | 是 | 是 | 是 | 是 |
| 创建自己的策略/任务、下载自己的结果 | 是 | 是 | 是 | 是 |
| 修改模板公开状态及公开参数 | 是 | 否 | 否 | 否 |
| 管理本公司货盘素材上下架 | 是 | 是 | 否 | 否 |
| 创建邀请、管理货盘用户 | 是 | 是 | 否 | 否 |
| 查看全公司货盘使用记录 | 是 | 是 | 否 | 否 |
| 分配货盘管理员 | 是 | 否 | 否 | 否 |
| 通过货盘获得内部经营数据权限 | 按原角色 | 按原角色 | 按原角色 | 否 |

首期由公司管理员和货盘管理员创建邀请，外部用户不开放转邀请权限。建议默认邀请有效期 7 天，可设置最大注册人数并随时撤销。

邀请注册流程：

1. 管理员生成邀请链接，记录公司、邀请人、有效期、使用次数上限和状态。
2. 被邀请人打开链接，页面展示公司和邀请人，填写姓名、邮箱、密码。
3. 注册事务锁定邀请记录，校验有效期、公司/邀请人状态、名额及邮箱唯一性。
4. 服务端创建 `SUPPLY_USER`，写入 `invited_by_user_id`、`invitation_id` 和注册时间，扣减邀请名额。
5. 注册成功登录后仅进入所属公司的货盘。

邀请 token 只保存哈希。前端提交的公司 ID、邀请人 ID 或角色不能作为可信归属，所有归属由 token 对应记录决定。撤销邀请不自动停用已经注册的用户；停用用户是单独操作。

邀请归属默认不可修改。邀请人离职或账号停用后仍保留历史归属和显示快照。已有账号不能通过另一邀请自动更换所属公司；跨公司使用、多公司加入首期不开放。

## 5. 模板公开与素材上架的两层控制

**模板公开是准入条件，素材上架是具体发布动作。** 开启模板公开不会把该模板下的所有历史素材自动公开，后续新生成的素材也不会自动上架。

模板公开建议要求：

- 属于当前公司，模板处于可用状态；首期公司只能发布公司自有模板，平台模板需先复制为公司模板。
- 产品描述完整，尺码/规格有效，物流重量及长宽高均大于零。
- 已设置管理员审核过的英文兜底基础标题。
- 需要尺码图的用途必须具备可公开读取的尺码图；具体类目的要求在策略校验中再次检查。
- 模板关键字段公开发布时形成版本，更新时重新校验。

素材上架建议要求：

- 素材属于本公司，具备有效基础 SKU，关联模板已公开。
- 图片是可靠、长期可用的公开 HTTPS 图片；外部临时链接素材先转存 R2 再上架。
- 公开图片与素材原始记录分开保留发布快照；同一素材仅对应一条货盘条目。
- 是否被内部草稿使用不影响货盘上架。现有 `MaterialAsset.usage_status` 不用来统计货盘用户使用情况。

批量上架先返回逐条校验结果：可上架数量和不可上架原因，例如模板未公开、SKU 缺失、图片转存失败。执行时再次检查，以防预览后状态发生变化。

建议规则：模板取消公开后，该模板货盘素材统一下架；再次公开后需显式重新上架。取消公开和素材下架都阻止新任务选材。已排队或执行中的相关任务在安全检查点停止；已成功生成的历史文件按正常保留期限可下载。

提供独立的“紧急撤回”操作：撤销受影响的历史文件下载、取消活动任务并留原因。已被用户下载的文件无法收回，撤回事件不能删除历史使用审计。

删除来源素材时同步下架对应货盘条目。货盘中正在使用、任务已引用的图片不能因普通素材删除或 Excel 过期被自动删除。公开货盘图片需要独立的长期保留和引用检查规则。

## 6. 策略配置与生成前检查

用户提出的参数全部保留，但 Excel 导入还需要库存、类目必填属性和部分模板基础数据。

| 参数 | 规则 | 数据来源 |
| --- | --- | --- |
| 策略名称 | 用户填写，便于重复执行 | 用户输入 |
| 店铺类型/导入模板 | 选择公司开放的 TikTok 类目库，同时显示本土/跨境类型 | 类目管理 |
| 商品类目 | 只能选择所选类目库内的类目，保存 ID 和名称 | 同现有 TikTok 导出弹窗 |
| 产品模板 | 选择本公司已公开、有效的产品模板 | 公开模板 |
| 售价 | 大于零，使用 Decimal 保存，并按选定模板规则限制 | 用户输入 |
| 每链接 SKU 图数量 | 固定整数 5–9 | 用户输入 |
| 链接数量 | 固定整数 10–100 | 用户输入 |
| 库存 | 建议默认 999，可修改 | 同现有导出能力 |
| COD | 仅本土模板支持时显示，建议沿用现有默认 Y | 导出能力 |
| 商品属性 | 随类目展示必填/选填和单选、多选、文本输入 | 类目解析结果 |
| 标题补充要求 | 可选，受模板事实约束 | 用户输入 |
| 素材复用 | 允许跨链接复用，同链接禁止重复，首期固定规则 | 已确认需求 |

当前“类目管理”中的数据实际是具名的导入类目库，一个店铺类型下可能存在多份文件。策略应保存具体 `category_catalog_id`，不能只保存“本土店/跨境店”。只开放 `tiktok_local` 和 `tiktok_cross_border`，Shopee 数据不进入该功能。

公司管理员在类目管理增加“开放给货盘使用”设置，避免外部用户读取全部内部类目配置。首期不再额外拆一个独立店铺类型字典，页面将“类型 + 类目库名称”组合展示。币种和站点跟随选定导入模板；存在多币种需求时，应补充受管理的币种元数据，不能由用户随意选择未受模板支持的值。

**“每链接 SKU 数量”建议在页面明确标为“每链接 SKU 图数量（款色数）”。** 现有导出会把每张 SKU 图与模板尺码组合展开。若一个链接包含 8 张 SKU 图，模板有 5 个尺码，则该链接有 40 个最终变体，20 个链接需要 800 行数据。

提交前和 Worker 选材前均检查：

- 账号/公司有效，模板仍公开，类目库仍开放，策略权限正确。
- 可用且不同基础 SKU 的素材数量至少达到每链接图数 `x`，不要求达到 `x × n`。
- 类目和必填属性合法、描述和物流完整、尺码图符合要求。
- 最终行数 `n × x × 尺码数量` 不超过实际导入模板容量，并检查平台变体限制。
- 模板/类目适配器兼容，售价、库存、图片和导出 SKU 合法。

生成确认区展示：“本次生成 20 个商品、每商品 8 个款色、预计 800 行；跨商品可复用”。如果只有 8 张素材而每链接使用 8 张，所有链接的素材集合必然相同，应直接提示用户。允许继续生成，但不同标题不代表商品内容有明显差异。

策略可保存、复制、编辑、停用。运行中的任务使用提交时的策略快照，之后编辑策略不影响历史任务。模板取消公开、类目库取消开放、公司或账号停用，仍会阻止任务继续使用。

## 7. 后台生成流程与任务状态

```text
用户选择策略 → 提交任务 → 参数校验及配置快照 → MySQL 持久队列
    → Worker 原子领取 → 随机选材并保存分组
    → 每链接独立生成标题 / 重试 / 兜底
    → 保存货盘商品草稿 → 校验及生成 XLSX
    → 上传私有 R2 → 发布成功记录与使用明细 → 用户授权下载
```

建议提交返回 HTTP 202 和任务 ID。关闭页面、退出登录、刷新浏览器不会中断正常后台任务；账号停用或任务取消会阻止继续处理。

任务状态与处理阶段分开：

| 状态 | 含义 |
| --- | --- |
| `queued` | 待领取 |
| `running` | 已领取，按阶段处理 |
| `retry_wait` | 技术故障后等待恢复处理 |
| `completed` | Excel 已写入 R2，数据库已提交可下载记录 |
| `failed` | 无法完成，显示明确原因，可按规则重试 |
| `cancelled` | 用户取消、权限变化或管理员撤回 |

`running` 阶段细分为选材、生成标题、构建表格、上传文件。前端显示真实计数，例如“标题 37/50；AI 成功 34；模板兜底 3”，完成记录带兜底标记。下载是否过期、是否被撤回作为独立文件状态，不覆盖任务完成历史。

生成记录展示任务号、策略名称、模板、图数、链接数、状态、阶段、标题进度、兜底数量、创建/完成时间、文件有效期和操作。

## 8. 选材、分组和导出 SKU

首期采用“用户历史较少使用的素材优先、本任务分配较少的素材优先、同优先级随机”的抽样规则。无须全表 `ORDER BY RAND()`；使用可用 ID 集合、使用统计和持久化随机种子。

每个链接抽取 `x` 条不同素材和不同基础 SKU。不同链接允许复用，尽量避免完全相同的素材集合；素材不足以形成不同组合时允许重复集合，并在生成前提示。素材属于同一产品模板，按保存的随机顺序排列图片。

分组结果一次提交入库，保存链接序号、选材顺序、来源素材 ID、货盘条目 ID、图片快照、源 SKU 和模板版本。任务恢复时读取这些分组，不重新抽样。

源素材 SKU 保持永久不变。为跨链接复用，建议给货盘导出添加稳定的链接编码，例如：

```text
源 SKU：Y1AA000001
货盘导出 SKU：Y1AA000001-G8F2L03-S
              源SKU       链接编码 尺码
```

`G8F2L03` 示例表示系统分配的稳定任务/链接码，实际需具有唯一性。同一链接的重试、同一文件重复下载不改变编码；新的任务使用新的编码。无尺码时省略尺码段。

数据库分别保存 `source_sku` 和 `seller_sku`，不能把链接编码写回素材库基础 SKU。订单导入现有代码按第一个 `-` 前内容聚合基础 SKU，有利于保持源 SKU 追溯；上线仍需针对新格式回归订单归集、平台 SKU 长度和 TikTok 导入行为。导出器增加可选的逐变体 SKU 映射，原公司草稿导出继续沿用原格式。

## 9. DeepSeek、重试与标题兜底

当前个人 DeepSeek 密钥按内部员工保存。货盘推荐新增**公司货盘专用 DeepSeek 凭据**，由公司管理员配置，加密存储。货盘管理员和用户只能看到是否已配置，不能读取密钥。记录任务调用量、使用模型及可取得的 Token 数据，便于控制费用。

任务中每个链接的标题独立处理，一个失败不会阻塞其他链接。默认使用首图和公开模板中的标题规则，并提供实际商品类目及有事实依据的补充要求。模板字段和模型输入只使用已经审查的商品事实，不让模型猜测材质、功能等属性。

现有调用向 `deepseek-flash` 传入 `image_url`，本方案不能据此认定真实服务一定支持图片。实施时需用测试凭据验证实际端点和模型能力；若配置模型仅支持文本，改用审核后的模板事实与素材标签，不能直接假定可看图。模型名称及是否支持图片应改为明确配置。

推荐默认 **首次调用 + 最多 3 次重试，总计最多 4 次调用**；将参数命名为 `max_attempts=4`，避免“重试三次”和“总共三次”混淆。

| 失败类型 | 处理 |
| --- | --- |
| 超时、网络问题、HTTP 429/5xx | 例如 2、8、20 秒退避并加随机抖动；429 优先遵守 Retry-After |
| 空标题、格式错误、长度不合规 | 重试时明确输出要求；达到上限后兜底 |
| 同批标题重名 | 首次生成后统一规范化检查；用稳定系列编码消除重名并复检 |
| 密钥无效、余额不足、模型/参数不支持 | 不重复消耗同一批剩余调用；按公司凭据熔断，采用有效兜底并提示管理员 |

兜底不建议拼无意义随机数。产品模板增加“货盘兜底基础标题”，例如已审核的：

```text
Printed Long Sleeve Nursing Maxi Dress
```

生成失败时追加固定系列编号：

```text
Printed Long Sleeve Nursing Maxi Dress - Style G8F2L03
```

这只表示内部款式编号，不增加未经确认的商品属性。编号由已保存的链接码生成，重试结果稳定。当前 `title_template` 是给 AI 的指令，不能直接用来当兜底成品标题。

最终统一校验：英文单行、不带说明或 Markdown、长度 25–255、去掉大小写与多余空格后同批不重名。为系列编号预留长度，先截取完整词边界再拼编号。发布模板时检查基础标题长度及有效性，防止兜底也无法导出。

建议初始任务并发 2、单任务标题并发 3，均可配置并受公司限流控制。任务详情记录每链接的 `title_source=ai/fallback`、尝试次数和错误类别。用户可看到哪些标题兜底，未来可增加编辑标题并生成文件新版本。

## 10. 商品草稿的归属

推荐首期新增独立的 `SupplyProductDraft`，保留与现有草稿一致的业务内容：模板、商品名称、说明、图片、SKU 明细、尺码图、售价、库存、属性，并归属货盘任务和外部用户。

独立保存的原因：现有草稿有分发、AI 图片制作、审核、妙手、HubStudio 和“已发布”等内部工作流程。货盘生成不需要这些流程，外部用户生成的 100 个链接不应进入员工待处理列表或内部发布统计。

提取公共商品数据校验和 Excel 构建服务，供两种草稿复用。货盘生成完成意味着可导出的商品草稿已经形成，不触发现有 `/drafts/export-tiktok` 的状态更新。

任务页面提供每链接的只读明细。首期不增加另一套商品草稿导航；后续如需外部用户编辑，再提供货盘草稿编辑及文件版本机制。

## 11. 队列恢复、幂等与故障处理

继续使用 MySQL 持久队列，新增 `supply-generation-worker`，首期不增加 Redis/Celery。不要用 FastAPI 请求进程内的 `BackgroundTasks` 承载长任务。

必要机制：

- 原子领取：`SELECT ... FOR UPDATE SKIP LOCKED`。
- 租约与心跳：例如每 15 秒续租、90 秒过期；领取时递增执行代号，旧 Worker 失去租约后不能提交结果。
- 短事务：选择分组、提交标题、发布结果分阶段提交；网络调用期间不持有长数据库事务。
- 幂等提交：`company_id + owner_user_id + idempotency_key` 唯一；相同 key 不同参数返回冲突。
- 分组/草稿唯一：每任务每链接一份草稿；每链接每货盘条目一条使用明细。
- 恢复检查点：选材保存后不重选；成功标题不重做；仅上传失败时不再调用 DeepSeek。
- 技术重试与标题重试分开：R2 临时故障不增加标题调用次数；无效参数、权限撤回等不自动重试。
- 用户取消、公司/账号停用、模板撤回或素材下架，在领取、选材、长阶段间、最终发布前重新检查。

R2 与 MySQL 无法组成同一个事务。先上传对象并核对大小/校验值，再用执行代号检查任务仍由当前 Worker 拥有，最后提交完成状态和成功使用记录。上传后数据库提交失败时可恢复核对该对象；未被数据库引用的对象进入清理流程。

选材分组与下架操作需要共享短事务锁或发布版本校验。最终发布也必须校验权限与素材可用性，不能只在 API 提交时检查。

Worker 重启后仅接管租约已过期任务，不能直接把所有 `running` 任务重置为排队，因为未来可能有多个 Worker。

## 12. R2 与文件下载

建议复用私有导出桶，增加通用文件函数；配置名可继续兼容现有 Hub 导出设置，货盘使用独立目录：

```text
supply-exports/company/{company_id}/user/{user_id}/task/{task_id}/v1.xlsx
```

数据库保存对象 key、文件名、大小、SHA-256、版本、生成/过期时间和撤回状态。采用稳定对象身份及分版本写入，避免重试生成大量无关联对象。

下载流程：用户点击自己的任务 → 后端验证账号、所属公司、任务所有者、文件未过期/撤回 → 生成例如 5 分钟有效的签名 URL → 下载。

公司管理员/货盘管理员可在明确管理权限下查看本公司任务明细和下载，用于处理问题并记审计；默认不开放普通用户之间的下载或分享。数据库不保存短时签名 URL，签名链接过期后可重新授权获取。

建议 Excel 默认保留 30 天，任务摘要、来源和使用记录继续保留；文件过期提示重新生成。图片保留策略独立于 Excel，不能随 Excel 清理而删除用户已用于商品链接的图片。

不要把 Excel 放在图片公网桶并永久裸链公开。下载日志区分“授权链接已签发”和“已确认完成下载”；普通签名链接只能确认前者，不能假装浏览器一定保存成功。业务统计“下载请求次数”应使用这个明确口径。

## 13. 使用记录与统计口径

“谁用过”建议定义为：**谁成功生成了包含该素材的 Excel**。选中素材、标题尝试、任务失败和重复下载不能重复累计使用次数。

保留三个层级：

1. 分配明细：选材时记录，被哪个任务/用户分配，最终是成功、失败还是取消。
2. 成功使用明细：任务完成提交时生效，一条明细对应某任务的某链接中的某素材。
3. 下载授权记录：记录操作者、任务、时间及结果，不再次累计生成使用。

| 统计 | 计算口径 |
| --- | --- |
| 使用用户数 | 成功任务中用户去重 |
| 成功生成任务数 | 包含素材的成功任务去重 |
| 链接使用次数 | 成功链接中的素材出现次数 |
| 最近使用时间 | 最近成功生成时间 |
| 下载请求次数 | 获得授权下载链接的请求数 |

如果同一用户的一次成功任务在 10 个链接里使用同一素材：用户数是 1，任务数是 1，链接使用次数是 10。该用户重复下载三次只增加下载请求次数，不增加生成使用。

详情保留公司、用户、邀请人及注册归属、策略/模板版本、任务、链接序号、源素材和源 SKU、导出 SKU 映射、完成时间。用户或素材下架/停用后仍可查看历史快照，计数不能因重试或删除而重复/丢失。

## 14. 数据模型建议

所有关系遵守现有项目约定：MySQL 不创建外键，通过普通关联 ID、索引、唯一约束及应用校验维护。

| 表/模型 | 重点字段或约束 |
| --- | --- |
| `User` 扩展 | `SUPPLY_USER`、`invited_by_user_id`、`invitation_id`；公司归属不可由客户端选择 |
| `SupplyAdminGrant` | 公司、内部用户、授权人、授权/撤销时间；公司与用户唯一 |
| `SupplyInvitation` | 公司、邀请人、token 哈希、期限、名额、使用次数、撤销状态 |
| `SupplyCompanySetting` | 加密 DeepSeek 凭据、模型能力、并发/每日额度、文件保留天数 |
| `SupplyTemplatePublication` | 公司/模板、是否公开、当前版本、发布人/时间、兜底基础标题 |
| `SupplyTemplateRevision` | 公开字段快照、版本号、发布时校验结果；发布记录与版本唯一 |
| `SupplyCatalogPublication/Revision` | 货盘开放状态、原类目库 ID、不可变模板文件及解析快照 |
| `SupplyItem` | 公司、来源素材唯一、模板、SKU/图片快照、上架状态、操作者、时间、版本 |
| `SupplyStrategy` | 公司、用户、类目库/类目、模板、价格、库存、图数、链接数、属性及状态 |
| `SupplyGenerationTask` | 参数/模板/类目版本、种子、状态/阶段、计数、租约/执行代号、幂等键、文件元数据 |
| `SupplyProductDraft` | 任务、链接序号、用户、商品内容、标题来源和重试次数；任务与序号唯一 |
| `SupplyUsageDetail` | 公司、任务、链接、素材、顺序、源 SKU/图片/导出 SKU 快照、最终结果 |
| `SupplyDownloadLog` | 任务、操作者、授权时间、结果 |
| `SupplyAuditLog` | 授权、上下架、公开状态、邀请撤销、用户停用和紧急撤回 |

若将使用明细同时作为选材持久记录，应以任务最终状态判断是否计入成功统计；不要另建一套会在重试时重复插入的“成功事件”。

模板和类目库版本应保存可恢复的真实数据。只保存版本号而没有对应原始 Excel/解析快照，无法在文件更新后恢复原任务。可用任务记录直接保存引用到不可变版本，避免每次复制完整大文件。

常用索引：

- 货盘浏览：`company_id + status + template_id + id`。
- 我的策略/任务：`company_id + owner_user_id + created_at + id`。
- Worker：`status + next_retry_at + created_at + id`，租约过期索引。
- 使用追溯：公司与素材/用户/邀请人/完成日期组合。
- 唯一约束：token 哈希、来源素材、用户提交幂等键、任务链接序号、链接素材明细。

推荐通过独立 `APIRouter` 增加 `/supply` 接口，不把新功能继续堆入主文件。

| 接口组 | 主要操作 |

| `/supply/items` | 货盘浏览、SKU 筛选、分页、详情 |

后端建议新增 `supply/models.py`、`schemas.py`、`router.py`、`permissions.py`、`generation.py` 和 `worker.py`；共享导出服务可从现有 `main.py` 提取。前端建议独立货盘页面与外部登录壳，避免扩大已很大的 `App.vue`。

所有旧内部业务入口需要显式角色准入，包括素材查询/删除/下载、模板内部详情、草稿、店铺、上传签名、AI 任务、个人资源及管理接口。前端隐藏菜单仅改善体验，后端仍是权限依据。直接改变 URL、公司 ID、用户 ID、任务 ID 都不能绕过限制。

## 16. 配额、验证与实施顺序

首期建议可配置：每用户最多 1 个活动生成任务、每任务最多 100 个链接、每公司受限的任务/标题并发、每日链接生成额度。管理员页面展示当日任务数、链接数、AI 调用量、兜底比例和失败原因；不依赖模型凭据隐式控制成本。

分五个交付阶段，每阶段完成后验证实际流程：

| 阶段 | 交付 | 主要验收 |
| --- | --- | --- |
| 1. 权限与发布 | 身份、附加授权、邀请注册、模板/类目开放、素材上下架 | 公司隔离与外部用户不能访问内部 API |
| 2. 货盘与策略 | 页面、公开模板、联动类目属性、策略管理、预校验 | 图数/链接数边界、材料不足、实际行数 |
| 3. 异步生成 | 持久任务、分组、草稿、DeepSeek 重试/兜底、进度 | 同链接去重、跨链接复用、断点恢复与标题唯一 |
| 4. 文件与审计 | XLSX、私有 R2、下载、有效期、使用明细 | 真实导入文件、失败状态、统计去重及撤回 |
| 5. 联调上线 | 回归、迁移、限流、配置、运维说明 | 现有员工草稿/导出不回归，公司邀请闭环 |

核心自动化与集成验收：

1. A 公司用户无法查询、生成、下载 B 公司货盘数据；外部用户请求内部接口被拒绝。
2. 邀请到期、撤销、超额、并发抢最后名额、公司/邀请人停用和重复邮箱处理正确。
3. 模板公开不自动上架全量素材；素材下架、模板取消公开能阻止活动任务发布。
4. 可用素材少于 `x` 拒绝；只有 `x` 个时允许跨链接复用且正确提示重复组合。
5. 同链接素材和基础 SKU 不重复；尺码展开、链接编码与源 SKU 映射正确。
6. 超时/429/5xx、无效密钥、非法标题、重名、全批兜底均产生可解释结果。
7. Worker 在选材后、标题过程中、上传后中断，恢复时不重复抽样、建草稿或计数。
8. 多 Worker 领取、租约过期和旧 Worker 提交冲突不会发布重复结果；锁行为在 MySQL 8 验证。
9. R2 上传失败不能显示完成；签名到期可重新授权，其他用户不能下载，文件撤回立即生效。
10. 同素材跨 10 个链接为 10 次链接使用、1 次任务使用；重试和重复下载不重复累计。
11. 回归现有本土/跨境导出，验证原工作簿说明页、图片、验证规则及尺码展开保真。
12. 使用独立测试 DeepSeek 凭据和私有 R2 桶做一次真实闭环，并用目标 TikTok 模板进行导入验证；服务可用性和平台 SKU 规则不以 mock 测试代替。

通过新的 Alembic 迁移增加结构，不修改已发布迁移，不清空原数据。内部旧账号和模板/素材默认不获得新增外部身份、不自动公开。

本机所有 Compose 运维使用 `./deploy/local.sh`；腾讯云使用 `./deploy/tencent.sh`。新增 Worker 加入对应环境配置，沿用迁移先完成再启动服务的机制，保留已有环境文件和数据库卷。

后续可扩展：货盘草稿编辑、标题重新生成和文件版本、跨任务避免重复组合、按邀请人结算、外部用户多公司加入、计费和定时生成。上述内容不影响首期完整闭环，但不应成为第一版的交付前提。
